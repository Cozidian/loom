## Grok

Honest ranking: **codex 9**, **grok 8**, **claude 7**. Codex is the only one with a real failed run (9 workers, ~190 model calls, ~720 tools, 8 writes, no completion) and it found two show-stoppers the others missed: Codex is a new ephemeral thread per step, and `template: "implement"` can spawn a so-called implementer with write tools stripped. Grok has the best statement of the experiment — Goal coordinates, models are workers, project processes hold truth — but it over-weights the org chart and under-weights bugs that already prevent a patch. Claude has the best cheap wins (parallel reads, non-blocking spawn, stop silent review) and correctly myth-busts image paste, but it treats SHA-gated edits as minor and never reaches construction, providers, or the repository index.

Best changes, in the order I would actually do them:

- **Make the default implementer able to land a patch.** Fix the `implement` / `implementer` trap so implementation work always gets write tools. Drop `expected_sha256` from the model schema; keep hashes in `RepositoryIndex` and return a numbered window plus nearby context on stale edits. Number `read_file` content. Return tool results as text. Treat non-zero `mix test` as data, not a tool exception. Run independent reads/searches concurrently. Pin a capable model to the implementer for the worker's lifetime — do not re-route every step, and do not send delivery work to a small local model.
- **Stop using an LLM as the supervisor.** Goal should start an implementer (plus a short read-only investigate wave when the surface is unknown). `spawn_subagent` should return a handle and stream progress; the parent must not block on `ask`. `delegate_tasks` is Goal API, not a tool the model has to remember. One coherent patch has one implementer; do not spawn another after the same failure fingerprint.
- **Make verification a sibling process, not a silent serial audit.** Keep `Goal.Verifier`, but it is not the default cost of every turn and it must not describe passing checks as failed. Only failed checks go back to the implementer. Infrastructure / sandbox / provider failures are not code defects. A reviewer that cannot run tests does not get to reject work for missing test evidence. "Done" is a Goal state after evidence, not a model sentence and not a regex over "I'll start by…".
- **Use OTP for continuity and restart, not compaction.** If Codex/ChatGPT is in the path, one supervised provider-conversation process per worker: native thread, tools executed inside the same turn, cancel by killing the process. If the implementer stalls, persist diff / failing tests / files touched, kill it, respawn with `ContextStore` + current index. Inject git, diagnostics, and investigator notes at init — do not wait for `request_project_context`.
- **Quiet the project services so they help instead of drowning the goal.** `RepositoryIndex` should honor `.gitignore`, skip build/tmp/session dirs, debounce, and publish coalesced deltas. Stop writing one `file_changed` into every session log. Path-lease the implementer. Worktrees and `/race` are Goal policy for isolated or checkable work, not prompt-time heuristics and not something to build before a normal feature lands.
- **Show work, not telemetry.** Goal-level transcript plus a live tree (investigating / writing / verifying / blocked on approval). Raw events stay in `/events`. User steering is a mailbox message into the running Goal, not a cancelled turn.
- **Do not build more control plane first.** No more templates, envelopes, routing evidence, or a large typed-artifact framework until one feature-sized ask completes on the default path. The work-contract idea from Codex is right as a _small_ invariant ("implementation has a write path; aliases cannot change that"), not as another unfinished layer.

## Claude

Honest ranking: **codex 9.3**, **grok 8.5**, **claude (mine) 7**. Codex wins because it has actual failure evidence — a real 5-hour, 9-worker, zero-completion run — and it found two concrete, reproducible bugs neither of the other two analyses touched: the `implement`/`implementer` template-vs-strategy naming collision that silently strips write tools from an agent whose role literally says "implementer," and the Codex App Server per-step ephemeral-thread/tool-ack race that trips `too_many_codex_tool_calls`. Those are smoking guns for "why doesn't it deliver," not inferred friction. Grok independently reaches the same core verdict as codex — Goal should be the actual supervisor/state machine, not an LLM roleplaying "coordinator" — and states it more crisply than either of the others, which is worth a lot on its own; it just never touches provider continuity, agent-construction bugs, or the repository index, so it stays one level more abstract than codex. Mine correctly found the sequential-tool-execution problem and the mandatory-review/regex-completion-policing tax, and correctly myth-busted image paste, but it's the narrowest of the three: it never looked at agent construction, the Codex provider path, or `RepositoryIndex`, so it caught design complaints rather than the bugs actually blocking delivery.

Best changes, my honest priority order combining all three analyses:

- **Fix the two concrete bugs first, before any redesign.** The `implement`/`implementer` naming collision that strips write tools from an implementer, and the Codex App Server per-step thread/tool-ack discontinuity that causes `too_many_codex_tool_calls` (both codex's find). These aren't architecture debates — they're why real sessions fail to land a patch today.
- **Make `Goal` the actual coordinator, not an LLM playing one.** This is the one idea grok and codex arrived at independently, which is the strongest signal in this whole exercise. Goal should classify the request, spawn the implementer (plus a short investigate wave when needed) itself, own restart/kill decisions, and decide when work is "done" from verification evidence — not from parsing the model's sentence.
- **Give workers project truth at construction time**, not as a tool they must remember to call: git status/diff, diagnostics, prior investigator findings, relevant file windows. Combine with restarting a stuck/looping worker from persisted artifacts plus fresh context instead of compacting its transcript.
- **Stop making the model a transaction manager.** Drop `expected_sha256` from the tool schema; check staleness against `RepositoryIndex` generations instead, and return a fresh numbered window on conflict rather than an opaque hash-mismatch error.
- **Make tool execution concurrent by default** for independent/read calls (`Task.async_stream`, same as `DecompositionExecutor` and `Goal.Race` already use), and **make `spawn_subagent` non-blocking** — return a handle and stream progress instead of blocking the parent's tool call on `ask`.
- **Make verification/review evidence-driven and non-blocking-by-default.** Only failed checks go back to the model, passing checks are never reported as failed, infrastructure/sandbox/provider failures are never treated as code defects, and review is a Goal decision gated on real test evidence — not a silent mandatory tax with a regex checking whether the model "sounds done."
- **Quiet `RepositoryIndex` down.** Honor `.gitignore`, exclude build/tmp/session directories, debounce instead of full-tree rescans every two seconds, and stop writing a `file_changed` event into every active session's log — pure noise that drowns the goal without improving model context.
- **Promote `Goal.Race` and worktree isolation from a hidden heuristic to a visible, Goal-decided (or user-invocable) capability**, and make the TUI show goal-level work phases (investigating / implementing / verifying / blocked) instead of raw event telemetry. That's the actual "Claude can't give you this" experience, and right now it's built but invisible.
- **Don't add more templates, capability envelopes, or routing machinery** until one real feature-sized request reliably completes end to end on the default path. All three analyses converge on this: the control plane is already ahead of the wiring.

## Codex

- Make the OTP `Goal` process own execution instead of starting every request as an LLM with a coordinator prompt. Turn the user request into a typed work contract, let the runtime select the initial worker shape, and keep model-proposed delegation as an optional signal rather than the mechanism that operates the tree.
- Add a supervised, persistent provider-conversation actor per worker. For Codex App Server, retain the native thread and execute each dynamic tool request through BeamAgent's `ToolRunner` and `ToolPolicy`, returning the real result to that same turn instead of rebuilding an ephemeral transcript for every step.
- Fix agent-construction invariants immediately. Replace arbitrary template strings with validated kinds or aliases, and reject any worker whose role, execution strategy, expected artifact, and effective capabilities contradict one another. An implementation worker must never silently become a read-only investigator.
- Make worker completion artifact-based. Implementers should return a patch artifact containing changed files, diff identity, decisions, and focused-check evidence; verifiers should return a verification artifact; reviewers should consume both rather than rediscovering work from an isolated conversation.
- Keep deterministic verification, but move it out of the model loop and into the Goal state machine: candidate patch → focused verification → repair with only failed evidence → final broader verification → risk-based review. Classify infrastructure, provider, approval, and code failures separately so environment failures never trigger repeated code rewrites.
- Add goal-level no-progress detection and failure fingerprints. If several workers hit the same blocker or keep reading the same evidence without changing the candidate, stop spawning clones. Restart a confused worker from durable artifacts and current project state, or surface the concrete blocker to the user.
- Give each worker a runtime-assembled context packet at startup: acceptance criteria, git status and diff, relevant repository files, current diagnostics, prior worker findings, last failed checks, and explicit touch scope. Project truth should come from supervised project services, not from a tool the model must remember to call.
- Keep observed-state edit safety, but make the runtime the transaction manager. Track file generations and path leases per worker; let the model use exact edits without carrying SHA values through its prompt; on stale state, return a fresh numbered window and nearby context.
- Redesign the coding-tool surface for model efficiency: numbered file reads, `read_files`, bounded searches with surrounding lines, concise text-oriented results, non-zero command exits as structured diagnostic data, and phase-specific tools. Run independent read-only calls concurrently under supervised tasks while serializing writes by path or workspace ownership.
- Replace the polling repository index with an incremental, debounced project service that honors ignore rules, excludes BeamAgent/build/cache data, coalesces repository changes, and keeps project telemetry out of conversational event logs.
- Lease a model to a work unit instead of rerouting every step. Use the strongest configured coding model for the primary implementer, cheaper/local models for bounded investigation or summarization, and carry provider-native reasoning, output-budget, continuity, and modality controls in the endpoint contract.
- Make the TUI a live goal-and-worker interface rather than an event transcript: semantic work blocks, current phase, active worker, elapsed time, blocker, approvals, verification state, detached/background status, and actions to steer or cancel one worker without losing the goal. Preserve raw events in the inspector.
- Stop adding more templates, policy metadata, or routing evidence until one self-hosted vertical slice reliably lands a multi-file feature. Use a task such as file-reference suggestions or image paste as the benchmark and track completion rate, wall time, model calls, tool calls, repeated failures, writes, verification, and user interventions.
